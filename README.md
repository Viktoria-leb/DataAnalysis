- Реализовано консольное аналитическое приложение на Java с трёхзвенной архитектурой, строго разделив ответственность слоёв: интерфейс работал только через бизнес‑логику, а доступ к данным инкапсулировал чтение/запись файлов.
- Настроена обработка входных параметров через аргументы командной строки (три файла: accounts.txt, transactions.txt и выходной файл для результатов); добавил валидацию количества аргументов и обработку исключений при отсутствии файлов.
- Разработана система гибкой фильтрации транзакций по нескольким критериям (категория, диапазон дат, диапазон сумм, комментарии) с объединением условий по логике «И»; реализовал нормализацию ввода (регистр, подстрочный поиск для комментариев).
- Внедрены механизмы группировки транзакций по разным полям (месяц, год, день недели, категория, тип счёта, ID пользователя, доходы/расходы) и агрегации данных (сумма, среднее, количество) с использованием обобщений (дженериков) и коллекторов для избежания дублирования кода.
- Учтена специфика типов транзакций, округление значений до двух знаков по стандартным правилам.
- Обеспечен вывод аналитики в консоль с метаданными (дата расчёта, выбранные фильтры, группировка, агрегация) и экспорт результатов в JSON‑файл с сохранением всей контекстной информации.
- Реализованы собственные бизнес‑исключения для обработки нештатных ситуаций (ошибки чтения файлов, некорректные форматы данных) и покрыл ключевые сценарии обработки ошибок.
- Использовались Lombok для сокращения шаблонного кода (геттеры, сеттеры, equals/hashCode/toString) и Gradle как систему сборки; интегрировал Git‑практики (ветки, коммиты с понятными сообщениями, отсутствие TODO‑комментариев в финальной версии).
